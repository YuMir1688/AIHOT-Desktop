# 开发与验证

## 构建流程

在 Windows、PowerShell 7 和 .NET 10 SDK 环境中运行根目录的 `build.ps1`。

1. 编译 `core/` 主程序，生成到 `artifacts/app/`。
2. 用生成的主程序集更新 `lib/` 中的历史兼容引用。
3. 编译增强模块和数据模块。
4. 使用 Mono.Cecil 将模块连接到主程序集，并移除全局快捷键。
5. 写入运行依赖清单。

此流程仍包含程序集补丁，并非所有模块都已迁移到普通项目引用。`lib/AIHOT.Desktop.dll` 会在构建时被源代码编译产物替换，不再是主程序的唯一实现。请不要手动混用历史 `app/` 文件和新构建产物。

## 验证范围

`test.ps1` 默认不访问实时数据，检查分页、130 条无截断、跨日过滤、未来时间过滤、重复条目、空列表、重复游标、Telegram 去重与分享渲染连接。

可选联网测试：`dotnet run --project modules/HotTests/Test.csproj -- --live`。该测试使用独立临时数据目录，但依赖上游服务可用且当天存在资讯，不适合作为纯离线验收标准。

## 已知限制

- 从早期主程序源码重建后，个别界面细节仍需人工回归；不能保证与历史打包程序逐字节一致。
- 现有截图展示维护者本地程序，不是自动构建逐版本生成的截图。
- UI 中保留部分历史术语（例如 TOP）；它不改变当前当天动态的分页与筛选规则。
- API 字段、网络和第三方内容都可能变化；本项目不保证内容完整性或新闻真实性。
- Releases、`app/` 和源码的更新节奏不同，以各自版本说明为准。

## 历史规则

项目曾使用“补齐 100 条”“过去 48 小时热榜”等规则。当前主线采用北京时间当天动态；旧说明和旧提交仅用于追溯，不作为当前使用指南。
